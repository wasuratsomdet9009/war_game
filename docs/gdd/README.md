## 1. GDD นี้คืออะไร

GDD คือเอกสารออกแบบเกมฉบับขยายที่แปลงสเปกของผู้ออกแบบ (Master Prompt v3.1) เป็นกติกา สูตร โครงสร้างข้อมูลเชิงแนวคิด และแผนพัฒนาที่ทีมนำไปสร้างเกมได้จริง โดยยึดหลักเหล่านี้ทุกบท

| หลัก | ความหมาย |
|---|---|
| ข้อที่ล็อกแล้ว (สเปก 0.6 และ 108.1) | มุมมองแผนที่ Top-down ที่ซูมต่อเนื่องจากแผนที่โลกลงถึงยานพาหนะคันเดียว อาคาร 2.5D ยกนูนเล็กน้อย ภายในอาคารเป็น Floor Plan Overlay ไม่มีกล้องระดับถนนหรือมุมบุคคลที่หนึ่ง · เล่นบน macOS เท่านั้น บน MacBook Pro M4 Pro RAM 24 GB แบบ Native ARM64 + Metal |
| ยังไม่เขียนโค้ด | ตามหัวข้อ 118 Data Model เป็นตารางหรือโครงสร้างเชิงแนวคิดเท่านั้น |
| ตัวเลขเป็นค่าตั้งต้น | ทุกตัวเลขต้องวัดหรือทดสอบจริงแล้วปรับ |
| จริยธรรม (สเปก 101) | ไม่มีทหารเด็ก ไม่มีกลไกทรมาน การผลิตอาวุธแสดงแบบนามธรรม ไม่ใช้รหัสลับจริง ผู้ช่วย AI ไม่ใช้ใบหน้า เสียง หรือตัวตนของบุคคลจริง |
| ไม่ลดรายละเอียดของสเปกโดยไม่มีเหตุผล | ทุกการเปลี่ยนแปลงบันทึกไว้ในส่วน "สิ่งที่เปลี่ยนจาก spec" หรือ "การตัดสินใจ" ของแต่ละไฟล์ |
| แม่แบบรายระบบ | ทุกบทที่อธิบายระบบใช้หัวข้อ 12 ข้อของสเปก 117 (แม่แบบ T1–T12 ใน [สารบัญ หัวข้อ 1](round-01/05-gdd-table-of-contents.md)) |

## 5. สรุปรอบที่ 1 — การตัดสินใจที่สำคัญที่สุด

| 2 | **โลกเดียว หลายวงความละเอียด (Detail Rings)** ประเทศเดียวละเอียดเต็ม เพื่อนบ้านแบบสรุป ประเทศอื่นเป็น Exogenous Actor แล้วขยายด้วยการเลื่อนขั้นวง แผนพัฒนาเป็น ระยะ 0 Spike → Prototype 2×2 กม. → MVP 1 จังหวัด → VS 3–5 จังหวัด → F1 ประเทศ / F2 ภูมิภาค / F3 โลกและอวกาศ | ขยายจากประเทศไปโลกได้โดยไม่รื้อ และอยู่ในงบตัวเกม 8 GB | [03 R-01](round-01/03-design-rulings-sec114.md), [04](round-01/04-phased-roadmap.md) |
| 3 | **สถาปัตยกรรม 34 โมดูลใน 6 ชั้น** มีผู้เขียนข้อมูลคนเดียวต่อข้อมูลหนึ่งชิ้น, Command API เป็นประตูเดียวของผู้เล่น กฎอัตโนมัติ ผู้ช่วย และ AI ทุกฝ่าย, ความจริงแยกจากความรู้ (Fog of War), สมุดบัญชีการไหล 3 เล่มและทะเบียน 2 ชุดที่ตรวจกฎ "ห้ามสร้างจากความว่างเปล่า" ได้ด้วยเครื่อง | ความยุติธรรม การเล่นซ้ำ และการตรวจสอบได้ ต้องออกแบบไว้ตั้งแต่ต้น | [02](round-01/02-system-map.md) |

## คำถามถึงผู้ออกแบบ (รอบที่ 1)

ตามสเปก 118 รอบนี้ถามเฉพาะ 3 ข้อในหัวข้อ 108.2 ทุกข้อมีค่าเริ่มต้นให้ทีมเดินงานต่อได้ถ้ายังไม่ได้คำตอบ ตอบสั้น ๆ เป็นตัวอักษรของตัวเลือกได้เลย

**1. ใครจะเขียนโปรแกรม กี่คน และถนัดภาษาอะไร**

- จำนวนคนเขียนโปรแกรม: (ก) ยังไม่มี / ผู้ออกแบบจะเริ่มเรียนเอง · (ข) 1 คน · (ค) 2–3 คน · (ง) 4 คนขึ้นไป
- ภาษาที่ถนัดที่สุด: (1) C# · (2) TypeScript · (3) Rust · (4) TypeScript + Rust · (5) Swift · (6) อื่น ๆ (โปรดระบุ เช่น C++ หรือ Python)
- **คำตอบเปลี่ยนอะไร:** เลือก Engine ตาม [ADR-0001 หัวข้อ 4.5](../adr/ADR-0001-tech-stack.md) — C# หรือยังไม่มีทีมใช้ Unity 6 LTS, TypeScript/Rust ใช้ Web Map Stack (MapLibre / deck.gl ใน Tauri + ระบบจำลอง Rust), Swift ต้องทดสอบเทียบกับ Unity ก่อน (Bake-off) · ภาษาของเครื่องมือแปลง OSM · ลำดับและการทำงานขนานของ Spike และขนาดงานใน [04 หัวข้อ 10.3](round-01/04-phased-roadmap.md)
- **ถ้ายังไม่ตอบ:** ใช้ Unity 6 LTS ตามข้อเสนอหลักของสเปก (107.1) และเริ่มจาก Spike 2 (ระบบพิกัด) ซึ่งไม่ขึ้นกับ Engine มากนัก

**2. ผู้ช่วย AI ต้องเล่นแบบออฟไลน์ได้หรือไม่** (ผู้ช่วยแบบแม่แบบที่ไม่ใช้ LLM มีเสมอทุกตัวเลือก)

- (ก) **ไม่จำเป็น** — ออนไลน์ใช้ LLM บนคลาวด์ ออฟไลน์ใช้ผู้ช่วยแบบแม่แบบ
- (ข) **ต้องเล่นออฟไลน์ได้ แต่ตอนออฟไลน์ใช้ผู้ช่วยแบบแม่แบบก็พอ** — ไม่ต้องมีไฟล์โมเดล LLM ในเครื่อง
- (ค) **ต้องคุยแบบ LLM ได้แม้ออฟไลน์** — มีโมเดล LLM บนเครื่องเป็นตัวเลือกเสริม
- **คำตอบเปลี่ยนอะไร:** (ค) ต้องส่งไฟล์โมเดลขนาดประมาณ 2–5 GB แยกจากตัวเกม (บน Steam เป็นการดาวน์โหลดแยก ส่วน Build ทดสอบผ่าน git จะกินโควตา Git LFS) กันหน่วยความจำประมาณ 3–6.5 GB และให้ LLM ทำงานเฉพาะตอนหยุดเกมหรือความเร็ว ≤1× ส่วนภาษาไทยต้องผ่านการทดสอบคุณภาพใน Spike 5 (Apple Foundation Models ช่วยไม่ได้ เพราะยังไม่รองรับภาษาไทย) · (ก) และ (ข) ไม่ต้องมีไฟล์โมเดลและไม่ต้องกันหน่วยความจำ แต่ (ก) มีค่าใช้จ่ายคลาวด์ต่อเนื่องและต้องขอความยินยอมเรื่องการส่งข้อมูล
- **ค่าที่ทีมแนะนำ:** ออกแบบให้เล่นออฟไลน์ได้ โดยผู้ช่วยแบบแม่แบบเปิดเสมอ LLM บนเครื่องเป็นตัวเลือก และ LLM บนคลาวด์ให้ผู้เล่นเปิดเอง ([03 R-13](round-01/03-design-rulings-sec114.md)) ผู้ออกแบบเลือกต่างได้ เพราะทุกแบบใช้ส่วนต่อประสานเดียวกัน
- **ถ้ายังไม่ตอบ:** สร้างผู้ช่วยแบบแม่แบบให้ครบก่อน ช่วงพัฒนาใช้ LLM บนคลาวด์ และวัดโมเดลบนเครื่องใน Spike 5 แล้วตัดสินค่าเริ่มต้นก่อนเริ่ม Vertical Slice

**3. จะใช้ประเทศหรือพื้นที่ใดทำ Prototype**

- (ก) ระบุประเทศ **และ** เมืองหรือย่านเอง (เช่น "ประเทศ X จังหวัด Y")
- (ข) ระบุเฉพาะประเทศ แล้วให้ทีมเลือกพื้นที่ตามเกณฑ์ใน [04 หัวข้อ 13](round-01/04-phased-roadmap.md) (ข้อมูลอาคารใน OSM ครบ มีโกดังหรือนิคมอุตสาหกรรม อาคารสูง โรงพยาบาล โรงเรียน และแม่น้ำในพื้นที่ 5×5 กม. เดียวกัน)
- (ค) ยังไม่กำหนด
- **คำตอบเปลี่ยนอะไร:** พื้นที่ทดสอบของ Spike 1 และพื้นที่ Prototype / MVP · เส้นเมริเดียนกลางของระบบพิกัด SimFrame และละติจูดที่กำหนดการขยายภาพของแผนที่ · คุณภาพข้อมูล OSM ที่ใช้ได้ · ชุดข้อมูลประเทศแรก ได้แก่ ระบบยศ เหล่า TO&E หน่วยงานรัฐ และลำดับเขตการปกครอง · ภาษาของชื่อสถานที่ใน Codex · ขนาดข้อมูลทั้งประเทศของ F1
- **ถ้ายังไม่ตอบ (ค):** Spike 1 ใช้ย่าน Vinohrady กรุงปราก **เป็นพื้นที่ทดสอบทางเทคนิคเท่านั้น** ไม่ใช่ฉากของเกม และออกแบบชุดข้อมูลประเทศให้เปลี่ยนได้

**ข้อที่ต้องยืนยันเพิ่ม (ไม่ใช่คำถามในหัวข้อ 108.2):** ผู้ออกแบบสั่งให้เกม "โหลดผ่าน git เท่านั้น" แต่สเปก 104 ระบุว่าจำหน่ายผ่าน Steam ตอนนี้เอกสารถือ git เป็นช่องทางเดียว และยังไม่วางแผนงาน Steam — ถ้าต้องการวางขายบน Steam ในอนาคตด้วย ให้แจ้งได้ ([ADR-0001 หัวข้อ 1.1 และ 10.3](../adr/ADR-0001-tech-stack.md))
