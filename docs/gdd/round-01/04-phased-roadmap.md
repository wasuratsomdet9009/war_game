# บทที่ 31 — แผนพัฒนาระบบแบบเป็นระยะ (Phased Development Roadmap)

> **สถานะ:** รอบที่ 1 — ร่างเพื่อให้ผู้ออกแบบทบทวน
> **แหล่งในสเปก v3.1:** หัวข้อ 103 (โมดูล 34 ตัวและข้อเสนอระยะ), 108.3 (Technical Spike), 104–106 (แพลตฟอร์มและงบประสิทธิภาพ), 102 (ระบบต้นทุนสูง), 4 (Scenario Scope), 114 (ประเด็นที่ต้องวัดผล), 109–112 (Scenario ตัวอย่าง)
> **เอกสารรอบที่ 1 ที่เกี่ยวข้อง:** [01 Vision & Pillars](01-vision-and-pillars.md) · [02 System Map](02-system-map.md) · [03 คำตัดสินประเด็น 114](03-design-rulings-sec114.md) · [05 สารบัญ GDD](05-gdd-table-of-contents.md) · [ADR-0001 Tech Stack](../../adr/ADR-0001-tech-stack.md)
> **กติกาของเอกสารนี้:** ตัวเลขทุกตัวเป็น **ค่าตั้งต้น (starting value)** ที่ต้องวัดจริงบน MacBook Pro M4 Pro 24 GB แล้วปรับ ไม่มีการสัญญาวันเวลา ขนาดงานบอกเป็น S / M / L / XL แบบสัมพัทธ์ และเอกสารนี้ไม่มีโค้ด

## สรุปย่อ

- แผนนี้มี **5 ระยะ**: **ระยะ 0 Technical Spike → Prototype → MVP → Vertical Slice (VS) → Full Vision** โดย Full Vision แบ่งเป็น 3 คลื่นตาม Scenario Scope ในหัวข้อ 4 คือ **F1 ประเทศเดียว (National Fracture) → F2 ภูมิภาค → F3 โลก + อวกาศ**
- **ระยะ 0** ทำ Spike 6 ข้อจากหัวข้อ 108.3 เรียงตามความเสี่ยง (และเสนอเพิ่ม S7 ข้อความภาษาไทย) ผลของระยะนี้คือ ADR-0001 ที่เปลี่ยนจาก "เสนอ" เป็น "ยอมรับ" พร้อมตัวเลขงบประสิทธิภาพที่วัดจริง
- **ทุกระยะต้องผ่านประตูคุณภาพเดียวกัน** บนเครื่องเป้าหมาย: 60 fps ที่ความละเอียดจริงของจอ หน่วยความจำไม่เกินงบในหัวข้อ 106.1 และทดสอบเล่นต่อเนื่อง 60 นาทีโดยไม่ลดความเร็วเพราะความร้อนจนเล่นไม่ได้
- **ฐานรากต้องมาก่อน**: ระบบพิกัด 64 บิต + Floating Origin → Tile Pipeline → Simulation Core แบบกำหนดผลได้ + Entity ID ถาวร + Save → **Command API** (ทางเดียวที่เปลี่ยนโลกได้) → ระบบโดเมน → AI → ผู้ช่วยนายพล
- ใช้ **Scenario A–D (หัวข้อ 109–112) เป็นแบบทดสอบการยอมรับ** ของแต่ละระยะ เพื่อวัดว่าระบบโต้ตอบกันจนเกิดเรื่องราวได้จริงโดยไม่ต้องเขียนสคริปต์
- เปลี่ยนจากข้อเสนอเดิม 20 จุด (ดูส่วนที่ 12) เช่น ย้าย Command API, Save และ Echelon Handoff test bench มาไว้ใน Prototype, แยกการสื่อสารพื้นฐาน (MVP) ออกจาก EW (VS) และบังคับให้ผู้ช่วย AI มีโหมดไม่ใช้ LLM ตั้งแต่ MVP

## 0. หลักการวางแผน

### 0.1 หลัก 8 ข้อที่ใช้ตัดสินว่าอะไรอยู่ระยะไหน

| # | หลัก | ความหมายในทางปฏิบัติ |
|---|---|---|
| 1 | **ลดความเสี่ยงที่ใหญ่ที่สุดก่อน (Risk-first)** | งานที่ถ้าล้มแล้วต้องเปลี่ยนเอนจินหรือสถาปัตยกรรม ต้องทำก่อนงานเนื้อหา |
| 2 | **ฐานรากต้องอยู่รอดทุกระยะ** | พิกัด, Tile, Sim Core, Entity ID, Save, Command API ออกแบบให้ขยายถึงระดับโลกตั้งแต่วันแรก แม้เนื้อหายังเล็ก (ตอบหัวข้อ 4: "ขยายได้โดยไม่ต้องรื้อใหม่") |
| 3 | **ทุกระยะเล่นได้จริง** | จบแต่ละระยะต้องมีประสบการณ์ที่ผู้เล่นทดสอบได้ ไม่ใช่ชุดระบบที่ยังไม่ต่อกัน |
| 4 | **วัดบนเครื่องจริงทุกระยะ** | ประสิทธิภาพเป็นเกณฑ์ผ่าน ไม่ใช่งานปลายทาง (ประเด็น M4 และ RAM 24 GB ในหัวข้อ 114) |
| 5 | **แนวตั้งก่อนแนวนอน** | ทำวงจรเดียวให้ครบลึกก่อน แล้วค่อยขยายพื้นที่และจำนวนเนื้อหา |
| 6 | **Data-driven ตั้งแต่ต้น** | อาวุธ อาคาร การดัดแปลง Codex และสี เป็นข้อมูล ไม่ฝังในโค้ด เพื่อเพิ่มเนื้อหาทีละระยะ (หัวข้อ 102) |
| 7 | **จริยธรรมเป็นเกณฑ์ผ่าน** | ทุกระยะตรวจรายการในหัวข้อ 101 เหมือนตรวจประสิทธิภาพ |
| 8 | **เสาหลักเป็นด่านคัดฟีเจอร์** | ฟีเจอร์ที่ไม่สนับสนุนเสาหลักข้อใดในหัวข้อ 0.3 ไม่เข้าระยะใดเลย |

### 0.2 สิ่งที่ล็อกแล้ว (หัวข้อ 0.6 และ 108.1) ซึ่งแผนนี้ถือตามโดยไม่เปิดประเด็นใหม่

- มุมมองแผนที่ **Top-down ที่ซูมต่อเนื่อง** จากแผนที่โลกถึงยานพาหนะคันเดียว อาคารเป็นรูปมุมบนยกนูนเล็กน้อยแบบ 2.5D ภายในอาคารเป็น **Floor Plan Overlay** ไม่มีกล้องระดับถนนหรือมุมมองบุคคลที่หนึ่ง
- **macOS เท่านั้น** บน **MacBook Pro M4 Pro, RAM 24 GB** Build แบบ **Native ARM64 + Metal**
- เครื่องพัฒนาคือ Mac เครื่องเดียวกัน (หัวข้อ 104) จึงต้องเผื่อหน่วยความจำให้ Editor ระหว่างพัฒนา

## 2. ระยะ 0 — Technical Spike

### 2.1 เป้าหมาย

พิสูจน์ด้วยตัวเลขที่วัดจริงว่าสถาปัตยกรรมในหัวข้อ 107.1 (Unity 6 LTS + Entities/Burst + ระบบ Map Tiles ที่สร้างเอง) ทำงานได้บน MacBook Pro M4 Pro 24 GB และเก็บผลไว้เป็นข้อมูลของ ADR ตามที่หัวข้อ 108.3 กำหนด ระยะนี้ไม่มีเกมเพลย์ ผู้เล่นยังไม่ได้เล่นอะไร สิ่งที่ "เล่นได้" มีเพียงฉากทดสอบ (Bench Scene) ที่ทีมใช้ซูม เลื่อน และดูตัวเลข

### 2.2 อันดับความเสี่ยงของ Spike ทั้ง 6 ข้อ

ความเสี่ยง = โอกาสที่จะไม่ผ่าน × ความเสียหายถ้าไม่ผ่าน (ต้องเปลี่ยนเอนจินหรือรื้อสถาปัตยกรรมหรือไม่)

| อันดับ | Spike (เลขเดิมใน 108.3) | ระดับความเสี่ยง | ทำไมเสี่ยงเท่านี้ |
|---|---|---|---|
| R1 | **S1 — OSM → Map Tiles หลายระดับ + วาดแบบนีออน** (ข้อ 1) | สูงมาก | เป็นส่วนที่ต้องสร้างเองทั้งหมด (107.1) เป็นหน้าตาของเกมทั้งเกม (เสาหลัก 1 และ 9) และเป็นจุดที่ตัดสินระหว่าง Unity กับ Web Map Stack (107.2) |
| R2 | **S3 — ECS จำลอง 5,000–10,000 หน่วย + หาเส้นทางบนถนน OSM** (ข้อ 3) | สูงมาก | ขนาดการจำลองคือแกนของเกม (106.2) ถ้าไม่ผ่านต้องลดเป้าจำนวนหน่วยหรือเปลี่ยนแนวทาง Sim Core ซึ่งกระทบทุกระบบ |
| R3 | **S2 — Floating Origin + พิกัด 64 บิต** (ข้อ 2) | ผลกระทบสูง / โอกาสล้มต่ำ | เป็นเทคนิคที่รู้จักกันดี แต่ทุกระบบอ้างอิงพิกัด ถ้าเปลี่ยนทีหลังจะแพงที่สุด จึงต้องล็อกให้เร็ว |
| R4 | **S4 — การแสดงผลตามระดับซูม Counter → ไอคอน → ภาพมุมบน** (ข้อ 4) | กลาง | เป็นความเสี่ยงด้านการอ่านง่ายและการเปลี่ยนภาพ แก้ซ้ำได้ แต่กำหนดสายการผลิตงานศิลป์ของหน่วยทั้งหมด |
| R5 | **S6 — เปิดเกมต่อเนื่อง 60 นาทีบน M4 Pro** (ข้อ 6) | กลาง | เป็นการทดสอบรวมของ S1+S3+S4 ถ้าไม่ผ่านไม่ต้องเปลี่ยนเอนจิน แต่ต้องลดงบทุกส่วน |
| R6 | **S5 — ผู้ช่วย AI เรียก Tool API ทั้งแบบคลาวด์และบนเครื่อง** (ข้อ 5) | กลางถึงต่ำ (ต่อแกนเกม) | มีโหมดไม่ใช้ LLM สำรองเสมอ (107.3) ความเสี่ยงหลักคือโมเดลบนเครื่องกินหน่วยความจำ 4–6 GB และแย่ง GPU |

### 3.2 วิธีวัดที่ใช้ทุกระยะ

- วัดจาก **Release Build** บนเครื่องเป้าหมาย เสียบสายชาร์จ ปิดโปรแกรมที่ไม่เกี่ยวข้อง บันทึกอุณหภูมิห้อง
- เครื่องมือ: Unity Profiler, Xcode Instruments (Time Profiler, Allocations, Metal System Trace), Metal Frame Capture (107.1)
- ฉากทดสอบมาตรฐาน **Bench-Proto, Bench-MVP, Bench-VS, Bench-F1** ใช้ seed และบันทึกคำสั่งตายตัว จึงรันซ้ำได้ผลเดิมเพราะระบบจำลองกำหนดผลได้
- รัน Bench อัตโนมัติเป็นประจำบนเครื่องเดียวกัน แล้วแจ้งเตือนเมื่อค่าใดแย่ลงเกิน 5% จากรอบก่อน

### 3.3 Determinism และ Save

- Replay จาก seed + บันทึกคำสั่ง ได้ Hash ของสถานะตรงกัน 100% บน Build เดียวกัน
- Save → Load → Hash ตรงกับก่อน Save และไม่มีสิ่งปลูกสร้างหรือยานพาหนะซ้ำ (หัวข้อ 87)
- Schema ของ Save มีเลขเวอร์ชัน และ Save ของระยะก่อนหน้าภายในระยะเดียวกันโหลดได้ (ข้ามระยะยอมให้ล้างได้จนถึง VS)

### 3.4 อ่านง่ายในพริบตา (เสาหลัก 9)

- ผู้ทดสอบบอกได้ว่าอะไรเป็นของใคร อยู่ในสถานะใด และอะไรอันตราย ภายใน 3 วินาทีต่อจุด อย่างน้อย 90% และหาหน่วยเดิมเจอหลังเปลี่ยนช่วงซูมภายใน 2 วินาที อย่างน้อย 90% (สองตัวชี้วัดเดียวกับ ADR-0001 Spike 4, VP4 ในไฟล์ 01 และ R-17) ทั้งในชุดสีปกติ ชุด Signal-CB และภาพจำลองการมองเห็นของผู้บอดสี
- ทุกข้อมูลสำคัญเข้ารหัสซ้อนด้วย สี + รูปทรง + ลวดลาย + ไอคอน + ป้าย (97)

## 4. ระยะ 1 — Prototype

### 4.1 เป้าหมาย

พิสูจน์วงจรยุทธวิธีหลัก **"ยึดตึก → ป้องกัน → ดัดแปลง"** บนแผนที่ OSM จริงในสไตล์นีออน โดยสร้างบนฐานรากที่จะอยู่ถึง Full Vision (พิกัด, Tile, Sim Core, Command API, Save) และวัดประสิทธิภาพจริงบน M4 Pro

### 4.2 เมื่อจบระยะ ผู้เล่น "เล่นอะไรได้"

ผู้เล่นคุม **หมวดทหาร 1 หมวด** (3 หมู่ นามเรียกขาน ANVIL-1 ถึง ANVIL-3 และรถบรรทุก 1 คัน) บนพื้นที่ OSM จริงขนาด 2×2 กม. ซูมได้ต่อเนื่องจากระดับเขต (Z9 ช่วงไอคอนที่ใช้ดูสถานะโซนรอบโกดัง) ลงถึงทหารรายตัว (Z19) ตรงกับช่วงซูม Prototype ใน R-17

1. สั่งการผ่าน **Radio Order Panel**: รูปแบบการเคลื่อนที่ Covert / Normal / March, ROE Weapons Free / Tight / Hold, พฤติกรรมเมื่อปะทะ, ระดับอิสระ Strict / Judgment / Initiative, ขอ SITREP และ Resupply ammo (27.1, 0.5 ข้อ 1)
2. เข้าตี **โกดังที่กลุ่มโจรขนาดหมวดครอบครอง** ใช้ที่กำบัง การยิงกดดัน และแนวสายตา แล้วเคลียร์อาคารทีละ Combat Cell ซึ่งดูได้เป็นแผนผังชั้นจากมุมบน
3. พบ **พลเรือนติดอยู่ในอาคารข้างเคียง** (จุดสีเหลือง) ROE จำกัดการยิง และสั่งอพยพได้
4. **เข้าประจำอาคาร** วางกระสอบทรายที่หน้าต่าง ปิดกั้นประตู แล้วตั้งรับการตีโต้
5. เมื่อการรบสงบและพื้นที่รอบโกดังกลายเป็นพื้นที่ส่วนหลังหรือพื้นที่สนับสนุน ก็ **ดัดแปลงโกดังเป็นคลังสิ่งอุปกรณ์** ได้ แล้วสั่งรถบรรทุกส่งกระสุนจากคลังให้หมู่ที่แนวหน้า
6. หยุดเกมเพื่อออกคำสั่ง ปรับความเร็วเวลา **Save แล้ว Load** ได้โลกเหมือนเดิมทุกอย่าง รวมความเสียหายรายอาคาร
7. สลับภาษาไทย/อังกฤษ และภาษาทหาร/ภาษาธรรมดา (ชุดคำย่อย)

ความยาวการเล่นหนึ่งรอบประมาณ 20–40 นาที (ค่าตั้งต้น)

## 5. ระยะ 2 — MVP

### 5.1 เป้าหมาย

ทำให้ **วงจร 3 ระดับ (ยุทธวิธี — ยุทธการและฐาน — ยุทธศาสตร์และเมือง) ต่อกันครบในพื้นที่หนึ่งจังหวัด** และพิสูจน์ทางเลือกหลักของเกม ได้แก่ ยึดหรือทำลาย, ขยายกว้างหรือยึดให้แน่น, และเกณฑ์ทหารหรือรักษาแรงงาน (Scenario B ข้อ 10, Scenario D ข้อ 5)

**การตีความข้อเสนอเดิม:** "หนึ่งเมืองหรือหนึ่งจังหวัด" → เลือก **หนึ่งจังหวัดที่มีเมืองหลักหนึ่งเมือง** เพราะต้องมีชนบท (อาหารและกำลังพล) และถนนระหว่างเมืองเพื่อพิสูจน์ Logistics Is Command ส่วน "5 กลุ่มอำนาจ" → ตีความเป็น **กลุ่ม AI 5 กลุ่มนอกเหนือจากผู้เล่น** ได้แก่ ชุมชนพลเรือน (9.1), อดีตกองทัพแห่งชาติ (9.5), อดีตหน่วยงานรัฐ/ตำรวจ/ฝ่ายปกครอง (9.6), กลุ่มขนส่ง (9.7) และกลุ่มโจร (9.8) ซึ่งมีบทบาทต่างกันชัดเจน (งาน 113 ข้อ 6) ถ้าทรัพยากรไม่พอ ให้ลดกลุ่มขนส่งเหลือเป็นการจราจรขนส่งที่เป็นกลางก่อน

### 5.2 เมื่อจบระยะ ผู้เล่น "เล่นอะไรได้"

1. เลือก **Origin 2–3 แบบ** (เช่น อดีตกองพันทหารช่าง, อดีตสถานีตำรวจ, กองกำลังอาสาสมัครชุมชน) และ **โหมดเริ่ม 2 แบบ** (เช่น Military Remnant และ Militia) บนจังหวัดที่กำหนด
2. รบระดับ **กองร้อยถึงกองพัน** มี **HQ หลักและ HQ เคลื่อนที่** ตั้งเสาอากาศบนอาคารสูงเพื่อขยาย Command Coverage และเห็นผลของ Command Delay
3. ขอยิงสนับสนุนจากปืนครกและปืนใหญ่ ใช้โดรนลาดตระเวน ยานพาหนะมีป้ายความเสียหายรายชิ้นส่วน และอาคารที่ถล่มปิดถนนได้
4. ยึดโกดังแล้ว **ขยายเป็นฐานระดับ 1–4 (Outpost → FOB)** วางกำแพงแบบลากเส้นพื้นฐาน สนามเพลาะ ลวดหนาม และด่านตรวจ
5. ยึดโรงงาน **ดัดแปลงเป็นโรงซ่อมหรือสายการผลิตพื้นฐาน** ตาม Conversion Matrix บางส่วน ต้องมีไฟฟ้า แรงงาน และวัตถุดิบ
6. ขบวนรถเคลื่อนที่จริงขน **สิ่งอุปกรณ์ 5 ประเภท** ถูกซุ่มโจมตีได้ และสินค้าที่ปลายทางขาดจริงเมื่อขบวนถูกตัด
7. **Manpower จากอำเภอที่ยึดได้** ตั้งนโยบายรับสมัคร ฝึกพื้นฐาน และเลือกว่าจะเกณฑ์ทหารหรือเก็บแรงงานไว้ในโรงงาน
8. ทหารบาดเจ็บถูกส่งกลับตามสาย **Role 1–2** ขอ 9-Line MEDEVAC และดัดแปลงโรงเรียนเป็นโรงพยาบาลสนาม
9. สร้าง **ลานจอดเฮลิคอปเตอร์และทางวิ่งสั้น Class A–B** เพื่อ MEDEVAC ขนส่ง และลาดตระเวน
10. ดู **Policy Dashboard พื้นฐาน** (KPI นโยบายชุดแรก การพยากรณ์อย่างง่าย)
11. ถาม **ผู้ช่วยนายพลระดับ 0 (Advise)** เช่น "ฐานไหนน้ำมันใกล้หมด" โดยอย่างน้อยต้องมีโหมดไม่ใช้ LLM
12. การรบที่ผู้เล่นไม่ได้ดูถูกคำนวณแบบ Operational Resolution และ **สลับเป็นการรบยุทธวิธีเมื่อซูมเข้า** โดยสถานะไม่เปลี่ยน
13. กลุ่ม AI ทั้ง 5 กลุ่มดำเนินกิจกรรมเองเมื่อผู้เล่นไม่ทำอะไร
14. เล่นบทฝึกสอนช่วงแรกของ "จากหมู่สู่กองพล" (91): คุมหมู่ยึดตึก → คุมหมวดและกองร้อย → ตั้ง HQ และเสาอากาศ

## 6. ระยะ 3 — Vertical Slice

### 6.1 เป้าหมาย

สร้าง **ชิ้นตัวอย่างที่มีคุณภาพระดับเกมจริง** ในภูมิภาคหนึ่ง พร้อม **ระดับยุทธการ** และระบบเชิงลึกจาก v2/v3 ได้แก่ ทหารรับจ้าง Lineage การสื่อสารและ EW การดัดแปลงเทคโนโลยี สนามบินครบทุกชั้นรันเวย์ ปฏิบัติการลำน้ำ ผู้ช่วยระดับเสนอและปฏิบัติ และกฎอัตโนมัติ เกณฑ์คือ "รู้สึกเหมือนเกมที่จะวางจำหน่าย" ทั้งภาพ เสียง UX และความลื่น และใช้เป็นฐานประเมินต้นทุนของ Full Vision

### 6.2 เมื่อจบระยะ ผู้เล่น "เล่นอะไรได้"

1. เล่นในภูมิภาค 3–5 จังหวัด เลือก Origin และโหมดเริ่มได้ประมาณ 4–5 แบบ
2. ใช้ **แผนที่ยุทธการ** (Z5–Z12) ที่มี Operational Counters แนวหน้า มาตรการควบคุม (Objective, Phase Line, Axis of Advance) และมอบแผนให้ **Commander AI ที่มีชื่อ ยศ และคุณลักษณะ** แตกเป็นภารกิจย่อย
3. มีการรบหลายจุดพร้อมกันโดยมี **กติกาความเร็วเวลา** ที่ผู้เล่นยังคุมได้
4. จ้าง **บริษัททหารรับจ้าง** จากตลาดที่มีจำนวนจำกัด ซึ่งอาจกักพื้นที่ไว้ถ้าจ่ายเงินช้า
5. ข้าศึก **หาทิศจนพบ HQ ส่วนหน้า** ผู้เล่นย้าย HQ เคลื่อนที่และสลับช่องทางตาม **PACE** ได้ รวมถึงรบกวนและดักฟังสัญญาณ
6. **รวมกองกำลังตำรวจ** เทียบยศ และรับมือก๊กเดิมใน Social Graph (Scenario C)
7. ผู้ช่วยเสนอ **แผน A/B** เรื่องรันเวย์ (Scenario D) ผู้เล่นให้อำนาจระดับ 1–2 ได้ มีผู้ช่วยหลายคนตาม S2 / S3 / S4 และทุกการกระทำอยู่ใน Action Log
8. เห็น **ฝูงโดรนบุกเข้าหาโดมป้องกันภัยทางอากาศแบบเป็นชั้น** และตั้ง **กฎอัตโนมัติ** เช่น "ถ้าเรดาร์ตรวจพบฝูงโดรน → กระจายรถน้ำมันออกจากคลัง"
9. ทำ **ปฏิบัติการลำน้ำ**: ข้ามแม่น้ำ เรือลาดตระเวน และท่าเรือเล็ก
10. พัฒนาเทคโนโลยีแบบ Salvage → Reverse Engineer → Modify → Prototype → Produce
11. ฟื้นฟูเมืองด้วย Zoning และ District สาธารณูปโภคไหลจริง และเมืองมีงบประมาณ
12. เปิดดู **Lineage, Chronicle และแฟ้มบุคคลพร้อม Social Graph** และพบว่าประวัติของภูมิภาคมาจาก **History Generation**
13. เล่นบทฝึกสอน **"จากหมู่สู่กองพล"** ครบทุกขั้น

### 10.4 ลำดับการตัดเมื่อทรัพยากรไม่พอ และสิ่งที่ห้ามตัด

**ตัดหรือเลื่อนจาก MVP ไป VS ตามลำดับนี้ก่อน** (ตัดข้อแรกก่อน)

1. Helipad และทางวิ่ง Class A–B (26) → เลื่อนไป VS ใช้ MEDEVAC ทางบกแทน
2. LLM ในผู้ช่วย → เหลือโหมดไม่ใช้ LLM อย่างเดียว
3. กลุ่ม AI ลดจาก 5 เหลือ 4 (ให้กลุ่มขนส่งเป็นการจราจรที่เป็นกลาง)
4. สายส่งกลับ Role 2 → เหลือ Role 1 + โรงพยาบาลสนามแบบนามธรรม
5. การทูตเหลือเฉพาะหยุดยิงและการค้า
6. Conversion Matrix เหลือ 6–8 คู่
7. โหมดเริ่มเหลือ 1 แบบ

**ห้ามตัดในทุกระยะ:** Tile Pipeline + ระบบพิกัด, Sim Core แบบกำหนดผลได้, Command API ทางเดียว, Save + Entity ID ถาวร, วงจรยึดและดัดแปลงอาคาร, Battlefield Zones, ขบวนรถส่งกำลังแบบกายภาพ, ทางเลือกเกณฑ์ทหารกับแรงงาน, การอ่านง่ายและชุดสี Signal-CB สำหรับผู้บอดสี (R-11), ภาษาไทย/อังกฤษ, รายการจริยธรรมในหัวข้อ 101, ประตูประสิทธิภาพบน M4 Pro
